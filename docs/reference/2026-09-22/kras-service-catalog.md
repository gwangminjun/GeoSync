# KRAS/KOREPS 서비스 ID 카탈로그 — 어떤 데이터가 어디에 있나

작성일: 2026-09-22

이 프로젝트가 **실제로 아는** 서비스 ID를 번호순으로 모았다. 출처는 세 곳뿐이다:
`docs/reference/2026-09-18/kras.md`(연계 규격서 §1~16), `kras.sync_dataset` 시드(DDL),
`api-test.html`의 API 목록. **세 곳 어디에도 없는 번호는 "모른다"고만 적는다** — 추측해서 채우지 않는다.

관련 문서: [구현 구조](./kras-ingest-structure.md) · [계약 검증 런북](./kras-contract-verification-runbook.md)

---

## 1. 한눈에

| 구분 | 개수 |
|---|---|
| 확인된 서비스 ID | **24개** (KRAS 19 + KOREPS 5) |
| 그중 적재 구현 완료 | **10개** |
| 구현했지만 ID를 모르는 데이터셋 | **7개** (kras.md에 규격은 있는데 ID가 없음) |
| ID는 아는데 규격(XML)을 모르는 것 | **14개** (kras.md에 해당 서비스가 아예 없음) |

**두 종류의 빈틈이 정확히 반대 방향이다.** 하나는 "무엇을 부를지는 아는데 응답을 모르고"(14개),
다른 하나는 "응답 구조는 아는데 무엇을 불러야 할지 모른다"(7개). 둘 다 연계 담당자 확인이 필요하다.

## 3. kras.md에는 있는데 서비스 ID를 모르는 것 — 7개

규격서에 요청 항목·응답 XML·샘플까지 다 있어서 **매퍼와 승격 로직은 이미 완성**돼 있다.
`connSvcId()`가 예외를 던져 실제 호출만 막혀 있는 상태다.

| kras.md | 서비스명 | 핵심 데이터 | dataset_code |
|---|---|---|---|
| §4 | 대지권등록부(건물조회) | **집합건물 동 목록 + 집합건물순번** — 아래 드릴다운의 출발점 | `collective_building` |
| §5 | 대지권등록부(전유부조회) | **전유부 동/층/호/실** | `collective_unit` |
| §6 | 대지권등록부 | **대지권 비율 + 소유권 연혁** (두 반복 그룹) | `land_right` |
| §9 | 집합건물소유권연혁 | 집합건물 소유권 변동 이력 | `unit_ownership_history` |
| §10 | 토지이동 변동내역 | **기간 내 토지이동 사건**(전/후 지번·지목·면적) | `land_change` |
| §13 | 건물통합정보 | **건물명·용도·구조·면적·층수 + 관련지번** | `integrated_building` |
| §14 | 건물통합도면 | 건물 배치도 이미지(base64) | `building_image` |

### §11·§12는 문서 자체가 잘못돼 있다

| kras.md | 서비스명 | 상태 |
|---|---|---|
| §11 | 소유권 변동내역 | **§10과 내용이 완전히 동일하게 중복 기재됨** — 필드명은 물론 샘플 응답값(`LAND_MOV_NO=27170012014200001800010001`)까지 같다 |
| §12 | 집합건물소유권 변동내역 | 위와 같음 |

복사-붙여넣기 오류로 보인다. 실제 응답을 받아야 진짜 구조를 알 수 있어 **구현하지 않았다**.

## 5. 중요도 관점 정리

### 지금 다 되는 것 — 토지 기본 계열
`KRAS000002`(대장) + `KRAS000003`(공유인) + `KRAS000006/7`(이력) + `KRAS000040`(전체 필지)
+ `KRAS000038`(도형) + `KRAS000039`(전체 지가).
**"필지가 무엇이고, 누구 것이고, 어떻게 변해왔고, 어디에 있고, 얼마인가"는 전부 수집 가능하다.**

### 가장 아쉬운 구멍 — 건축물대장 계열
`KRAS000014`(표제부+층별+소유자+변동, 4개 테이블), `KRAS000016`(전유부, 4개 테이블),
`KRAS000102/103`(동/호). **ID는 다 아는데 응답 XML 규격이 kras.md에 없다.**
건물 쪽 업무 테이블 13개가 통째로 비어 있는 상태다.

### 절반만 막힌 것 — 집합건물(대지권등록부) 계열
§4~6, §9는 반대로 **규격은 있는데 ID가 없다.** 매퍼·드릴다운 승격까지 완성돼 있어
서비스 ID 4개만 받으면 바로 켤 수 있다. 투입 대비 회수가 가장 좋은 구간이다.

### 토지이용계획 계열
`KRAS000025/26/27` — ID는 알고 규격은 없다. `KRAS000026`은 지도 이미지 파일까지 딸려 있어
`building_image`(§14)에서 만든 파일 저장 경로를 재사용할 수 있다.

## 6. 담당자에게 요청할 것 (이 문서의 실질적 결론)

1. **응답 XML 규격 14건** — KRAS000014·15·16·17·25·26·27·102·103, KOREPS00011·33·34·35·47
   (요청 파라미터 + 실제 응답 샘플)
2. **서비스 ID 7건** — kras.md §4·§5·§6·§9·§10·§13·§14에 해당하는 `conn_svc_id`
3. **kras.md §11·§12 정정본** — §10과 중복 기재된 문제
4. (참고) KRAS000001, 004~005, 008~013, 018~024, 028~036, 041~100 번호대에 우리가 모르는
   서비스가 더 있는지 — 현재 전체 목록을 받아본 적이 없다
