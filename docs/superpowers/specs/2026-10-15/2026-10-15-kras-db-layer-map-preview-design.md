## 1. 요구 (2026-10-15 사용자 결정)

| 항목 | 결정 |
|---|---|
| 대상 | 규격 §15 **SHAPE 다운로드** 행의 DB 테이블과 그 파생 뷰만: `public.lp_pa_cbnd`, `public.lt_c_uzone`, `public.v_lt_c_uzone_*` |
| 지도 서버 | 지오서버(YG-Space 작업공간). 주소는 yml에서 읽는다. 지금 주소는 `http://112.216.98.130:31022/geoserver/YG-Space/`이고 나중에 바뀐다. |

| 인터넷 | **계속 못 쓴다.** OSM 같은 외부 배경지도와 CDN 라이브러리를 쓰지 않는다. |

| 스타일 | 레이어 스타일은 포털이 정의한 `public.dhc_layer_style`을 따른다(§4.4). |

## 2. 사전 확인 (2026-10-15, 개발 PC)

### 2.1 지오서버
- WMS GetCapabilities가 응답한다(4.3MB, 느림). 팝업 뷰 이름과 같은 이름으로 레이어가 등록돼 있다: `v_lt_c_uzone_*`(각각 `_random_style` 짝 포함), `lp_pa_cbnd`, `lp_adm_emd`, `lp_adm_li`.
- `GetMap`(EPSG:5186, 800×400, 3개 레이어)은 1.4초에 PNG를 돌려준다. 좌표 변환 없이 5186 그대로 받을 수 있다.
- 범위가 넓은데 연속지적(약 25만 필지)을 같이 그리면 검게 뭉친다. dhc 축척 규칙(§4.4)이 이 문제를 막는다.
- 기관 12830의 범위는 `ST_Extent` 기준으로 X 107,823–167,701, Y 285,953–314,948이다. 행정경계 `lp_adm_emd`(12개)의 범위와 같다.

### 2.2 스타일 (`dhc_layer_style`)
- `dhc_layer_style`은 5,908행이다. `dhc_layer.layer_cd`로 1:1로 이어지고, 레이어 테이블 이름은 `dhc_layer.tb_schema`·`tb_name`에 있다.
  - 용도지역 뷰 중 스타일이 있는 것은 약 192개다(306개 중).
  - `lp_pa_cbnd`, `lp_adm_emd`에도 스타일이 있다.
  - 모두 면(`geom_type`=Polygon)이다.
- **지오서버 기본 스타일과 비교:** 지오서버에 등록된 기본 스타일(`*_random_style`)은 dhc와 색은 같다. 하지만 채움 투명도(0.7 vs 0.3), 선 굵기, 라벨 위치가 다르고 축척 규칙이 없다. 그래서 기본 스타일로는 포털과 똑같이 보이지 않는다.
- **dhc 값으로 만든 SLD를 `SLD_BODY`로 보내 시험:** GetMap이 정상 동작했다(URL 약 2.7KB, 200 image/png).
  - `uf801`과 `lp_adm_emd`를 그려 보니 색·선이 dhc 값대로 나왔고, 채움은 dhc 투명도(0.3)대로 옅게 나왔다.
  - 라벨은 글꼴(`label_font`=`Dialog`)을 지정해야 한글이 나온다. 지정하지 않으면 라벨이 빠졌다.
  - 축척 규칙(`min_scale`/`max_scale`)을 넣으면 지오서버가 그대로 지킨다. 1:44,000에서 `uf801`(1:500–1:5,000)은 그려지지 않았다.
- **축척 범위 예시:**

  | 레이어 | 표출 축척 | 라벨 축척 |
  |---|---|---|
  | `lp_adm_emd` | 0–1:250,000 | 1:250,000 |
  | `lp_pa_cbnd` | 1:200–1:2,000 | 1:1,500 |
  | `uf801` | 1:500–1:5,000 | 1:5,000 |

  용도지역 뷰 대부분은 1:500–1:1,000,000(152개)이고, 1:500–1:5,000,000이 36개다.

**결론: dhc 스타일대로 표출할 수 있다.** 서버가 dhc 행으로 SLD를 만들어 GetMap에 `SLD_BODY`로 붙이면 된다. 지오서버 설정은 바꾸지 않는다.

## 3. 지도 구현 방식 — 라이브러리 없이 WMS 이미지

인터넷이 없으니 CDN을 쓸 수 없다. 방법은 두 가지다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. WMS GetMap 이미지 + 직접 만든 이동·확대 (선택)** | 새 의존성이 없다. 5186 좌표를 그대로 쓴다(proj4 불필요). 코드 약 100–150줄. | 타일이 아니라서 움직일 때마다 이미지를 다시 받는다(약 1–2초). 회전·측정 같은 기능은 없다. |
| B. OpenLayers를 `static/`에 넣어 함께 배포 | 타일·부드러운 이동, 기능이 많다. | 약 1MB 라이브러리를 추가하고 버전을 관리해야 한다. 5186 정의(proj4)도 필요하다. |

미리보기 용도이고 의존성을 늘리지 않으려고 **A**를 택한다. 이동이 답답하다는 의견이 나오면 B로 바꾼다. 지도를 그리는 함수만 바꾸면 되고, SLD(§4.4)는 B에서도 그대로 쓸 수 있다.

## 4. 화면

### 4.1 진입

- 테이블 팝업 검색줄: `[칼럼 ▼] [검색어] [검색] [초기화] [미리보기]`
- [미리보기]는 지금 보고 있는 대상이 §1의 대상(SHAPE 다운로드 테이블과 그 파생 뷰)일 때만 보인다. 다른 테이블에서는 숨긴다.
- `geoserver.url`이 비어 있으면 버튼은 보이되 누를 수 없다. 버튼에 마우스를 올리면 "지오서버 주소(geoserver.url)가 설정되지 않았습니다"를 보여준다.

### 4.2 지도 팝업

```
┌ 지도 미리보기 — v_lt_c_uzone_uf801 · 산지관리/보전준보전산지                 닫기 ✕ ┐
│ [＋] [－] [전체 범위]  배경: ☑ 행정경계 ☑ 연속지적   ☐ 포털 표출 축척 적용(1:500–1:5,000) │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│                (WMS GetMap 이미지, 드래그로 이동·휠로 확대)                  │
│                                                                          │
├──────────────────────────────────────────────────────────────────────────┤
│ EPSG:5186 · 축척 약 1:50,000 · 범위: 기관 12830(검색 조건 반영) · 스타일: 포털(dhc)  │
└──────────────────────────────────────────────────────────────────────────┘
```

- **창:** 테이블 팝업 위에 겹쳐 뜨는 두 번째 팝업이다. 닫으면 테이블 팝업으로 돌아간다. 기존 `dset-modal` 스타일을 쓰고, z-index만 한 단계 높인다.
- **레이어 순서(아래 → 위):**
  1. 행정경계 `lp_adm_emd`
  2. 연속지적 `lp_pa_cbnd` — 미리보기 대상이 `lp_pa_cbnd` 자신이면 배경에서는 뺀다.
  3. 대상 레이어 — 테이블 팝업에서 고른 뷰 이름(스키마를 뗀 이름)
- 배경 두 레이어는 dhc 축척 규칙대로 보였다 안 보였다 한다. 예를 들어 연속지적은 1:2,000보다 확대했을 때만 보인다.
- 레이어마다 `<img>`를 하나씩 겹친다(GetMap 최대 3번).
  - 레이어별로 SLD를 따로 붙이고, 스타일이 없는 레이어는 지오서버 기본 스타일로 받기 위해서다.
  - 같은 범위·크기로 요청하므로 서로 어긋나지 않는다.
  - 배경 체크박스를 끄면 그 `<img>`만 숨긴다.
- **조작:** 드래그로 이동하면 놓을 때 다시 요청한다. 마우스 휠과 [＋]/[－]는 배율 2배씩이다. [전체 범위]는 처음 범위로 돌아간다.
  - 요청이 겹치면 마지막 요청만 반영한다(순번 비교).
  - 로딩 중에는 이전 이미지를 그대로 두고 "불러오는 중"만 표시한다.
- **이미지 크기:** 지도 영역의 실제 픽셀 크기로 요청한다. 고해상도 화면에서는 `devicePixelRatio`를 곱하되 최대 2배로 제한한다.
  - 축척은 CSS 픽셀 기준으로 계산하고, 그 축척에 맞춰 `WIDTH`/`HEIGHT`만 늘린다. 이렇게 해야 축척 규칙이 화면 배율과 상관없이 같게 적용된다.

### 4.3 처음 범위

- 서버에 `GET /kras-db/table/extent?name=…&col=…&q=…`를 부른다. 테이블 팝업에서 쓰는 조건(기관 필터와 검색 조건)이 같이 적용된 범위를 `ST_Extent(지오메트리 칼럼)`으로 구한다.
  - 예: pnu로 검색한 상태에서 미리보기를 누르면 그 필지들 위치로 바로 간다.
- 범위에 5% 여백을 두고, 지도 영역의 가로세로 비율에 맞춰 넓힌다.
- 행이 0건이면 지도 대신 "이 조건으로는 표시할 도형이 없습니다"를 보여준다. 이 기관 행이 없어 다른 기관에 행이 있는 경우는 표 팝업에서 이미 안내한다.

### 4.4 스타일 — `public.dhc_layer_style`

**레이어 찾기:** `dhc_layer`에서 `coalesce(tb_schema,'public').tb_name`이 레이어 이름과 같은 행을 찾고, 그 `layer_cd`로 `dhc_layer_style` 행을 가져온다.
- 같은 이름이 여러 행이면, 테이블 팝업에서 레이어 이름을 붙일 때(§9)와 같은 순서로 하나를 고른다: `use_yn='Y'` 우선, 그다음 최근 등록.

**칼럼별 SLD 변환:**

| dhc 칼럼 | SLD |
|---|---|
| `fill_yn`, `fill_color` | `PolygonSymbolizer/Fill` (`fill`, `fill-opacity`) |
| `line_yn`, `line_color`, `line_weight` | `Stroke` (`stroke`, `stroke-opacity`, `stroke-width`) |
| `min_scale`, `max_scale` | 도형 `Rule`의 `MinScaleDenominator`/`MaxScaleDenominator` |
| `label_yn`, `label_column` | 라벨 전용 `Rule`의 `TextSymbolizer/Label` (`PropertyName`). 칼럼이 레이어에 실제로 있을 때만 쓴다. |
| `label_scale` | 라벨 `Rule`의 `MaxScaleDenominator` |
| `label_font`, `label_style`, `label_font_size` | `Font` (`font-family`, `font-style`, `font-size`). 글꼴을 빼면 한글 라벨이 안 나온다. |
| `label_font_color`, `label_border_color`, `label_border_weight` | 라벨 `Fill`, `Halo`(`Radius`=굵기) |
| `label_sort`(center 등), `label_rotate` | `PointPlacement` 기준점(center → 0.5/0.5), `Rotation` |
| `marker`, `open_yn`, `sort` | 쓰지 않는다. 대상이 모두 면이라 `marker`가 필요 없고, 그리는 순서는 §4.2에서 정한다. |

**색 형식:** `rgba(r,g,b,a)` 문자열인데 a 값의 기준이 섞여 있다. 선은 대부분 0–255(`255`)이고 `1`이나 `100`도 있으며, 채움은 0–1(`0.3`)이다.
- 포털이 이 문자열을 브라우저에 그대로 넘긴다고 보고, 브라우저(CSS)와 같은 규칙으로 해석한다: **a가 1보다 크면 1(불투명)**.
- 예: `rgba(51,153,102,100)`은 불투명이 된다. 포털 화면과 다르게 보이면 이 규칙만 바꾼다.

**만드는 곳과 전달:** SLD는 서버(Java)에서 만들어 지도 범위 API(§5.2) 응답에 레이어별로 담는다. 브라우저는 그 SLD를 `SLD_BODY`로 붙이기만 한다. DB 값은 XML 이스케이프한다.

**스타일이 없는 레이어:** SLD 없이 지오서버 기본 스타일로 그린다. 지도 아래 안내에 "포털 스타일 없음 — 지오서버 기본 스타일"이라고 표시한다.

**축척 규칙과 미리보기:** 포털 규칙을 그대로 지키면 `uf801` 같은 레이어는 1:5,000 이하에서만 보인다. 800px 지도로 치면 화면 폭 약 1.1km다. 기관 전체 범위(약 1:280,000)에서 [미리보기]를 누르면 대상이 아무것도 안 보일 수 있다. 그래서 다음처럼 나눈다.
- **배경**(행정경계·연속지적)은 dhc 축척 규칙을 그대로 따른다.
- **대상 레이어**는 기본으로 축척 규칙을 빼고 항상 그린다. 색과 라벨(라벨 축척 포함)은 dhc 그대로다.
  - `☐ 포털 표출 축척 적용 (1:500–1:5,000)`를 켜면 축척 규칙을 넣어 포털과 똑같이 보인다.
  - 켰는데 지금 축척이 범위 밖이면 "이 축척에서는 포털에 표시되지 않습니다"와 [표시 축척으로 이동] 버튼을 보여준다.
- **축척 계산:** 지오서버는 OGC 표준(화소 0.28mm)으로 축척을 계산한다. 하단의 "축척 약 1:N"도 같은 식(`범위 폭 m ÷ CSS 화소 수 ÷ 0.00028`)으로 계산해, 표시하는 축척과 실제로 그려지는 기준을 맞춘다. 포털이 축척을 다르게 계산하면 경계 부근에서 조금 차이가 날 수 있다.

## 5. 서버

### 5.1 설정 (yml)

`src/main/resources/application.yml`에 기본값을 넣는다:

```yaml
geoserver:
  url: http://112.216.98.130:31022/geoserver/YG-Space/
  preview:
    background-layers: lp_adm_emd,lp_pa_cbnd   # 아래→위, 보이는 축척은 dhc_layer_style을 따른다
```

- **운영 서버는 이 값을 읽지 않는다.** 서비스가 `--spring.config.location=file:conf/application.yml`로 떠서, 클래스패스 yml은 아예 읽히지 않는다(`scripts/run.bat`, `install-service.bat`). 그래서 운영 반영 때는 사용자가 `conf/application.yml`에 같은 블록을 직접 넣어야 한다. 이 파일은 hook으로 막혀 있어 내가 수정할 수 없다.
  - 값이 없을 때를 대비해 `@Value("${geoserver.url:}")`처럼 기본값을 비워 둔다. 그러면 버튼만 비활성화되고 서비스는 정상으로 뜬다.
- 주소 끝의 `/`는 있든 없든 처리한다. WMS 주소는 `<url>/wms`로 만든다.
- 이 설정을 읽는 곳은 `KrasSchemaController` 하나다. 생성자 주입이 아니라 `@Value` 필드로 둔다. 기존 생성자와 그 테스트를 바꾸지 않기 위해서다.

### 5.2 API

`GET /kras-db/table/extent?name=public.v_lt_c_uzone_uf801&col=&q=` 의 응답:

```json
{ "previewable": true, "srid": 5186, "total": 6774,
  "bbox": [107823.0, 285953.4, 167700.9, 314948.0],
  "layers": [
    { "name": "lp_adm_emd", "role": "background", "title": "읍면동", "sld": "<StyledLayerDescriptor…>",
      "minScale": 0, "maxScale": 250000 },
    { "name": "lp_pa_cbnd", "role": "background", "title": "연속지적", "sld": "…", "minScale": 200, "maxScale": 2000 },
    { "name": "v_lt_c_uzone_uf801", "role": "target", "title": "산지관리/보전준보전산지",
      "sld": "…(축척 규칙 없음)", "sldWithScale": "…", "minScale": 500, "maxScale": 5000 } ] }
```

- **허용 규칙:** §1 대상만 받는다. 판정은 다음 순서다.
  1. 테이블 팝업의 허용 규칙(허용 테이블과 그 파생 뷰)을 통과해야 한다.
  2. 그 원본이 SHAPE 다운로드 행의 테이블(`SPEC_ITEMS` §15 `targetTable`을 나눈 집합)이어야 한다.
  - 그 밖의 테이블은 400 "지도 미리보기는 SHAPE 다운로드 레이어만 됩니다"로 거절한다.
- **지오메트리 칼럼:** `udt_name='geometry'`인 첫 칼럼을 쓴다(`geom` 또는 `_geometry`). 없으면 `previewable:false`.
- **조건과 안전장치:** WHERE(기관 필터, 검색 조건)와 안전장치(읽기 전용, 5초 제한)는 테이블 팝업과 같은 코드를 쓴다. `KrasTableBrowser`에 `extent(...)` 메서드를 하나 추가한다.
- **스타일:** `layers[]`의 `sld`는 §4.4대로 만든다. dhc 스타일이 없으면 `sld:null`이다. `dhc_layer`·`dhc_layer_style` 테이블 자체가 없는 DB에서도 `sld:null`로 동작한다.
- **SRID:** `ST_SRID`를 그대로 돌려준다. 5186이 아니면 지도 요청의 `SRS`를 그 값으로 쓴다. 지오서버가 해당 좌표계로 그려 준다.
- **지오서버 설정 전달:** 지오서버 주소는 페이지 모델로 JS에 넣는다(`KRAS_MAP_CONFIG`). 배경 레이어 목록은 서버가 `layers[]`에 넣어 준다.

### 5.3 WMS 요청 형식 (레이어 하나당)

```
<geoserver.url>/wms?SERVICE=WMS&VERSION=1.1.1&REQUEST=GetMap&FORMAT=image/png&TRANSPARENT=true
  &LAYERS=v_lt_c_uzone_uf801&STYLES=&SRS=EPSG:5186&BBOX=minx,miny,maxx,maxy&WIDTH=w&HEIGHT=h
  [&SLD_BODY=<dhc로 만든 SLD>]
```

- 1.1.1로 요청하는 이유: 1.3.0은 좌표계에 따라 BBOX 축 순서가 바뀐다.
- 레이어 이름은 작업공간이 URL에 들어 있으므로 접두어 없이 쓴다.
- `SLD_BODY`를 넣은 URL은 약 2.5–3KB다. GET 길이 제한(보통 8KB)에 들어간다.

## 6. 안 하는 것

- `dhc_layer_style`을 화면에서 고치는 기능. 이 기능은 읽기만 한다.
- 지도에서 도형을 클릭해 속성 보기(GetFeatureInfo): 지오서버 CORS 설정이 필요하다.
- 기관 조건으로 대상 레이어 거르기(`CQL_FILTER`): 범위만 기관 기준이고, 화면에는 레이어 전체를 그린다. 다른 기관 데이터가 함께 그려질 수 있다.
- 검색된 행 강조 표시
- 외부 배경지도(OSM, VWorld), GeoSync 서버를 거치는 중계

필요해지면 위 항목에서 하나씩 추가한다. 강조 표시와 기관 거르기는 `CQL_FILTER`나 SLD 규칙으로 할 수 있다.

## 9. 구현 결과 (2026-10-15)

- **설정 주입:** `geoserver.url`과 `geoserver.preview.background-layers`는 `@Value` 필드가 아니라 **생성자 인자**로 받는다. 프로젝트 규칙(생성자 주입)을 따른 것이고, 컨트롤러를 직접 만드는 테스트가 없어 영향이 없었다.
- **SLD 조회 수정:** `dhc_layer_style.line_weight`, `label_rotate`는 `float4`라서 JDBC가 Double로 변환하지 못했다. SQL에서 `::float8`로 바꿔 읽는다.
  - 테스트 DB(geosync_it)에는 dhc 테이블이 없어 이 문제를 잡지 못했고, 개발 서버에서 발견했다. 그래서 dhc 조회 자체는 DB 테스트 대신 개발 DB 수동 확인으로만 검증했다.
- **개발 서버(18080)와 지오서버 실측:** 브라우저 스크립트와 같은 식으로 GetMap을 만들어 받았다.
  - `v_lt_c_uzone_uf801` 범위 API: 0.5초, 6,774건. 응답 레이어 3개 모두에 dhc 스타일이 붙었다.
  - 1:294,043(기관 전체 범위): 대상이 dhc 색으로 그려진다. 행정경계는 포털 규칙(1:250,000 이하)에 따라 그려지지 않는다.
  - 1:147,021: 행정경계(라벨 포함)와 대상이 함께 보인다.
  - 1:1,470(포털 축척 적용): 연속지적(빨간 선, 지번 라벨), 용도지역 채움과 라벨, 읍면동 라벨이 모두 dhc 스타일로 나온다.
  - `lp_pa_cbnd`를 pnu 앞부분으로 검색한 범위(3,183건)와 `v_lt_c_uzone_uq112`를 alias로 검색한 범위(455건)도 정상이다.
- **원본 테이블 `lt_c_uzone` 자체:** 지오서버에 레이어로 등록돼 있지 않다. 레이어는 뷰 단위(`v_lt_c_uzone_*`)로만 있다. 그래서 원본을 미리보기하면 배경만 나오고, 지도 아래에 "지오서버에서 이미지를 받지 못한 레이어: lt_c_uzone"이 표시된다. 레이어별로 보려면 [보기]에서 뷰를 고른다.
- **확인하지 못한 것:** 화면에서 버튼을 누르고 드래그·휠로 움직이는 동작. 브라우저 자동화 도구가 없어 JS는 문법 검사만 했다.
- **운영 반영:** `conf/application.yml`에 `geoserver` 블록(§5.1)을 사용자가 직접 추가해야 한다.

## 10. 추가 — 행 한 건 미리보기 (2026-10-15)

- 사용자 요청: 검색된 행 중 한 건을 골라 그 행만 지도로 볼 수 있게.
- 표 맨 앞에 `선택` 라디오 칸(미리보기 테이블일 때만). 고르면 버튼이 `선택 1건 미리보기`로 바뀌고, 같은 행을 다시 누르거나 검색·초기화·보기 변경 시 해제된다. 페이지를 넘겨도 선택은 유지된다.
- 미리보기 테이블엔 PK가 없어 행 식별 칼럼을 실측으로 정했다(`ROW_KEY_COLUMNS` = mnum → pnu → uid): lt_c_uzone·뷰는 mnum, lp_pa_cbnd는 pnu가 행마다 유일(dev DB).
- `GET /kras-db/table/extent?key=` → 범위를 그 행으로 좁히고 `cqlFilter`(예: `mnum = '…'`, 따옴표 이중화)를 준다. 화면은 대상 레이어 GetMap에만 `CQL_FILTER`를 붙인다.
- **표현 통일(사용자 결정 2026-10-15):** 처음 구현에서는 대상과 이름이 같은 배경을 빼는 규칙(§5.2) 때문에 `lp_pa_cbnd` 한 건을 고르면 주변 필지가 사라지고, 고른 필지도 포털 스타일(빨간 선)이라 다른 필지와 구분이 안 됐다. `lt_c_uzone` 뷰는 배경 필지가 남아 두 테이블의 표현이 달랐다. 그래서 행을 골랐을 때만:
  - 대상과 같은 배경도 빼지 않고 주변 맥락으로 그린다(행을 안 골랐을 때는 종전대로 뺀다).
  - 대상 SLD(`sld`·`sldWithScale` 둘 다) 끝에 강조 규칙 `HIGHLIGHT_RULE`(노란 #FFD400 4px 선 + 채움 0.25)을 덧붙인다. 축척 규칙이 없어 포털 축척 적용 중에도 보인다. 포털 스타일이 없는 레이어는 강조만 있는 SLD.
  - 대상 판정은 이름 비교가 아니라 레이어 목록의 마지막(같은 이름 배경이 앞에 올 수 있어서).
- 결과: 두 테이블 모두 "배경(읍면동·연속지적) + 고른 행을 포털 스타일 위에 노란 강조"로 같게 보인다(지오서버 GetMap 재현으로 확인).
- 지오서버 확인: uf801 한 건(CQL) / 필터 없음 = 칠해진 화소 214 / 68,618. lp_pa_cbnd도 한 필지만 그려짐.
