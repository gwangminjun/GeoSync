# KRAS 연계 관리 — 적재 DB 테이블 조회 팝업 설계

- 작성일: 2026-10-15
- 상태: **구현 완료(미커밋, 2026-10-15)** — 설계와 달라진 점은 §8
- 범위: `/kras-db`(KRAS 연계 관리) 화면만. 기존 연계(`/conn`·`/svc`, synchronization)는 바꾸지 않는다.

## 1. 요구

규격 표의 **→ 적재 DB 테이블** 칸에서 테이블 이름을 누르면 팝업이 열린다. 팝업에서는 다음을 할 수 있다.
- 그 테이블에 적재된 행을 본다.
- 그 테이블 안에서 검색한다.

지금 이 칸은 `kras.land_register, kras.land_owner` 같은 글자일 뿐이다. 적재 결과를 확인하려면 DB 도구를 따로 열어야 한다.

## 2. 화면

### 2.1 진입

- `→ 적재 DB 테이블` 칸의 문자열을 `,`와 `→`로 나누고, 테이블 이름마다 버튼을 하나씩 만든다. 버튼 모양은 데이터셋 칸의 `spec-link-btn`과 같다.
  - 예: `kras.land_change_event → kras.parcel, kras.land_basic`는 버튼 3개가 된다. 화살표는 글자로 남긴다.
- 테이블이 DB에 없으면 버튼은 그대로 두고, 팝업 안에 "테이블이 아직 없습니다(마이그레이션 미적용)"를 보여준다.
- 데이터셋 팝업 카드의 `서비스 → 업무 테이블` 문구는 이번 범위에 넣지 않는다. 필요하면 같은 함수만 연결하면 된다.

### 2.2 팝업 구성

```
┌ kras.land_register  (기관 12830 · 30건)                     닫기 ✕ ┐
│ [칼럼 ▼ pnu      ] [검색어 ____________] [검색] [초기화]          │
│ ※ 기관코드(org_cd)=12830 행만 보입니다. 개인정보 칼럼은 가려집니다.  │
├──────────────────────────────────────────────────────────────────┤
│ register_id │ pnu                 │ jimok │ parea │ ... │ source_item_id │
│ 31          │ 1283099999190300000 │ 08    │ 120.5 │ ... │ 4411           │
│ ...                                             (가로 스크롤)       │
├──────────────────────────────────────────────────────────────────┤
│ 1–50 / 30건                                   [‹ 이전] [다음 ›]     │
└──────────────────────────────────────────────────────────────────┘
```

- 기존 데이터셋 팝업의 스타일(`dset-modal-backdrop`/`dset-modal`)을 그대로 쓴다. 팝업 요소는 하나만 두고, 열 때마다 내용을 바꾼다.
- 칼럼 목록과 순서는 DB 정의(`information_schema.columns`의 `ordinal_position`)를 따른다.
- 한 페이지는 50행이다. 정렬은 PK 내림차순(최근 적재가 위)이다.
- 칸의 글자가 80자를 넘으면 잘라서 보여주고, 전체 값은 `title`(마우스를 올리면 보임)에 둔다.
- `source_item_id` 칸은 수집 이력 팝업으로 연결한다(`?hist=<dataset>&item=<id>`, 이미 구현됨). 데이터셋은 버튼을 누른 행의 dataset_code를 쓴다.
- `Esc`나 배경을 누르면 닫힌다. 데이터셋 팝업과 같은 동작이다.

### 2.3 검색

- **칼럼 선택 + 검색어 1개.** 칼럼을 여러 개 조합하는 검색은 넣지 않는다.
  - 기본 칼럼: `pnu`가 있으면 `pnu`, 없으면 PK 첫 칼럼.
- 칼럼 형식에 따라 비교 방식이 다르다.

| 칼럼 형식 | 비교 | 예 |
|---|---|---|
| `pnu` | 앞부분 일치 `LIKE '검색어%'` | `12830` → 해당 시군구 전체 |
| 그 밖의 문자 | 부분 일치 `ILIKE '%검색어%'` | `대` |
| 숫자 | 같음. 숫자가 아니면 "숫자를 입력하세요"를 보여준다. | `4411` |
| 날짜·일시 | 그 날 하루(`>= d AND < d+1`). 형식은 `yyyy-MM-dd`. | `2026-10-15` |
| 공간·바이너리·개인정보 | 검색 칼럼 목록에서 뺀다 | — |

- 검색어가 비어 있으면 전체를 보여준다(기관 조건만 적용).
- `%`, `_`는 글자 그대로 찾도록 이스케이프한다.

## 3. 서버

### 3.1 API

`GET /kras-db/table?name=kras.land_register&col=pnu&q=12830&page=0` → JSON

```json
{
  "table": "kras.land_register",
  "exists": true,
  "orgFiltered": true,
  "orgCd": "12830",
  "columns": [{"name": "register_id", "type": "int8", "searchable": true, "masked": false}, ...],
  "rows": [[31, "1283099999190300000", ...]],
  "total": 30,
  "totalCapped": false,
  "page": 0,
  "pageSize": 50
}
```

`KrasSchemaController`에 메서드 하나를 추가한다. 조회 로직은 같은 패키지의 `KrasTableBrowser` 하나에 둔다. 테스트하기 쉽도록 SQL 조립을 정적 메서드로 뺀다.

### 3.2 안전장치

이 기능은 화면에서 받은 이름으로 SQL을 만든다. 그래서 아래 규칙을 반드시 지킨다.

1. **테이블 허용 목록:** `SPEC_ITEMS`의 `targetTable` 문자열을 나눠 만든 집합에 있는 이름만 받는다. 그 밖의 이름은 400으로 거절한다. 임의의 `kras.*`나 `public.*`는 받지 않는다.
2. **칼럼 검증:** `col`은 그 테이블의 `information_schema.columns` 결과에 있는 이름만 받는다. 식별자는 큰따옴표로 감싸서 넣는다.
3. **값 바인딩:** 검색어는 `?` 파라미터로만 넘긴다. 문자열을 이어 붙이지 않는다.
4. **읽기 전용:** `SELECT`만 실행한다. 트랜잭션은 `readOnly`이고, `SET LOCAL statement_timeout = '5s'`를 건다. 시간이 넘으면 "검색이 오래 걸려 멈췄습니다. 검색어를 더 좁혀 주세요"를 보여준다.
5. **건수 상한:** 전체 건수는 `SELECT count(*) FROM (… LIMIT 10001)`로 센다. 10,000건을 넘으면 `totalCapped=true`이고 화면에 "10,000건 이상"으로 표시한다. 큰 테이블(parcel 약 26만)에서도 건수를 세다가 멈추지 않게 하려는 것이다.
6. **page 상한:** `page`는 0–199까지만 받는다. 50행 × 200페이지 = 10,000행이다.

### 3.3 기관 필터

- 테이블에 `org_cd` 칼럼이 있으면 항상 `WHERE org_cd = <현재 기관>`을 붙인다. 화면에서 이 조건을 끌 수는 없다.
- `public.lp_pa_cbnd`처럼 `org_cd`가 없는 테이블은 조건 없이 보여주고, 안내 문구를 "기관 구분 칼럼이 없어 전체 행을 보여줍니다"로 바꾼다.

### 3.4 특수 칼럼

- **공간(`geometry`)**: 값 대신 `ST_GeometryType(geom) || ' / SRID ' || ST_SRID(geom)`를 보여준다. 좌표를 내려보내지 않으므로 응답이 커지지 않는다.
- **바이너리(`bytea`)**: `(바이너리 N bytes)`로 보여준다(예: 건물통합도면 이미지).
- **개인정보**: §4를 따른다.

## 4. 개인정보 — 확인 필요

`land_owner`, `land_share`, `land_ownership_history`, `unit_ownership_history` 등에는 소유자 이름(`owner_nm`)과 주소(`owner_addr`, `detl_addr`)가 들어 있다. 검증 근거 저장(`KrasVerificationEvidenceService.mask`)은 이미 이런 값을 가리고 있으므로, 이 팝업도 **기본은 가린다**.

| 칼럼 | 표시 | 검색 |
|---|---|---|
| `owner_nm` | 첫 글자만 보이고 나머지는 `*` (예: `홍**`) | 불가 |
| `owner_addr`, `detl_addr` | 앞 2어절만 보임 (예: `경기도 양평군 ***`) | 불가 |
| 주민번호 형식 값(어느 칼럼이든) | `[MASKED]` (기존 `RRN_PATTERN`) | — |

- 가림은 서버에서 한다. 원래 값은 응답에 들어가지 않는다.
- 가릴 칼럼 이름은 서비스 안 상수 하나로 둔다. 실제 테이블을 다시 확인해 구현할 때 목록을 확정한다.
- **결정 필요:** 운영 담당자는 소유자 이름으로 찾고 싶을 수 있다. 그 경우 대안은 "이름 같음 검색만 허용하고, 결과 표시는 여전히 가림"이다. 정해 주시기 전까지는 위 기본(가림, 검색 불가)으로 구현한다.

## 5. 하지 않는 것

- 행 수정·삭제, CSV 내려받기, 여러 칼럼 조합 검색, 칼럼 머리를 눌러 정렬 바꾸기
- 지도 표시(공간 칼럼)
- stage 테이블 조회: 수집 이력 팝업이 이미 다룬다.

필요해지면 위 API에 파라미터를 더해 확장한다.

## 8. 구현 결과 (2026-10-15)

- 조회 로직은 Spring 빈이 아닌 정적 유틸 `KrasTableBrowser`로 만들었다. 컨트롤러 생성자와 그 테스트를 바꾸지 않기 위해서다. 테스트 이름도 `KrasTableBrowserTest`, `KrasTableBrowserDbIntegrationTest`로 바꿨다.
- 가리는 칼럼(§4)은 실제 테이블을 확인해 확정했다.
  - 이름 `owner_nm`, 주소 `owner_addr`·`detl_addr`, 등록번호 `dregno`·`owner_regno`(값 전체를 `***`로 가림).
  - jsonb 칼럼(`extra_attributes`, `payload`)에 같은 이름의 키가 있으면 그 값도 가린다.
  - 모든 값에 주민번호 형식 안전망(`RRN_PATTERN`)을 적용한다.
- 화면에서 가린 칼럼에는 🔒 표시를 붙인다.
- 개발 서버(18080)와 개발 DB에서 확인한 결과:
  - land_owner는 `홍**`, `전라남도 장흥군 ***`로 가려졌다.
  - pnu 앞부분 검색: 10건. lp_pa_cbnd: `ST_MultiPolygon / SRID 5186`, 10,000건 이상.
  - 허용 목록 밖 테이블, 숫자 칼럼에 글자 입력, 201페이지 요청은 모두 400과 안내 문구를 돌려줬다.
- 브라우저에서 클릭하는 확인은 하지 못했다(자동화 도구 없음). JS는 `node --check`로 문법만 확인했다.

## 9. 추가: 파생 뷰 보기 (2026-10-15)

용도지역지구 `public.lt_c_uzone`은 레이어별 뷰 306개(`public.v_lt_c_uzone_<코드>`)로 나눠서 쓰고 있다. 정의는 두 종류다.
- `WHERE layer_code = '…'` 191개
- `WHERE theme_code = '…'` 115개

이 뷰들도 팝업에서 볼 수 있게 했다.

- **뷰 목록:** 팝업을 열면 `GET /kras-db/table/views?name=<테이블>`을 부른다. 그 테이블에서 파생된 뷰(`information_schema.view_table_usage` 기준)가 있으면 검색줄 위에 **보기** 선택이 나온다. 선택지는 다음 순서다.
  1. 원본 테이블
  2. `뷰 · 이 기관 행 있음` (건수 많은 순)
  3. `뷰 · 이 기관 행 없음`
- **건수 계산:** 정의가 `WHERE ((칼럼)::text = '값'::text)` 하나뿐인 뷰는 원본을 칼럼별로 `GROUP BY` 한 번씩만 센다. 306개 뷰의 건수를 쿼리 2번으로 구하고, 응답은 약 0.4초다. 모양이 다른 뷰(예: `kras.land_frst_ledg`)는 건수 없이 이름만 보여준다.
- **허용 규칙:** 화면 표에 있는 테이블을 원본으로 쓰는 뷰만 열린다. 그 밖의 뷰(예: `kras.api_current_response`)는 400으로 거절한다. 기관 필터, 개인정보 가림, 5초 제한, 건수 상한은 원본 테이블과 같다.
- **이 기관 행이 없을 때:** 검색하지 않은 상태에서 현재 기관 행이 0건이면, 다른 기관별 건수(최대 5개)를 함께 알려준다. 데이터가 없는 것과 기관이 다른 것을 구분하기 위해서다. 행 내용은 보여주지 않는다.
  - 개발 DB의 lt_c_uzone 17,658행은 모두 기관 46870 데이터라서, 개발 서버(기관 12830)에서는 "다른 기관 행: 46870 17,658건"으로 나온다.
- **레이어 이름(추가):** `public.dhc_layer`(지도 레이어 목록)에서 `tb_schema.tb_name`이 뷰 이름과 같은 행의 `title`을 붙인다. 같은 뷰가 여러 행이면 `use_yn='Y'`, 최근 등록 순으로 하나를 고른다.
  - 선택지는 `[UF801] 산지관리/보전준보전산지 · 6,774건` 모양이다.
  - **보기** 옆 입력칸에 레이어 이름이나 코드를 넣으면 선택지가 좁혀지고, 하나만 남으면 그 뷰가 바로 열린다.
  - 개발 DB 기준으로 306개 중 192개에 이름이 있다. `dhc_layer`가 없는 DB에서는 이름 없이 코드만 보인다.
- 팝업의 선택·입력칸은 어두운 테마(`.tbl-toolbar`, `color-scheme:dark`)로 맞췄다.
