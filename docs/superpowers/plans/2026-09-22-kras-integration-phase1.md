# KRAS 연계 관리 1차 구현 계획

**Goal:** 신규 연계의 실패 기록 보존, 수집 이력 조회·반영 이어하기, 사전 점검과 부분 실패 표시를 제공한다.

**Architecture:** 기존 수집 서비스와 DB 가드를 재사용한다. 별도 실행 로그는 수집 트랜잭션 밖에서 저장하고, 이력 조회 및 stage 미리보기는 기관과 서버의 매퍼 등록 목록으로 제한한다. 화면은 기존 카드 위에 통합 이력 영역을 추가한다.

**Tech Stack:** Java 17, Spring Boot, JdbcTemplate, PostgreSQL, Thymeleaf, JavaScript.

**Spec:** `docs/reference/2026-09-22/kras-integration-improvement-recommendations.md`의 1차 항목.

## 범위와 결정

- 사용자 지시인 권장 순서에 따른 구현 시작을 근거로 1차 작업을 현재 세션에서 진행한다.
- 작업 브랜치: `feat/kras-integration-phase1`. 사용자가 검토 중인 추천 문서는 보존한다.
- 예약·다건 수집, 비동기 실행, 화면 전체 재구성은 2·3차 후속 범위다.
- 추가 실행 기록 테이블은 `kras.ui_operation_log`이며 최초 실행 요청 시 없으면 생성한다. 기존 데이터 테이블은 변경하지 않는다.
- 기존 SUCCESS 수집 건은 반영 완료 상태와 구분한다. 새로운 반영 로그가 없는 과거 작업은 반영 여부를 단정하지 않는다.
- 공간 데이터의 과거 item을 임의로 게시하지 않는다. 이력에서 이어하기는 PNU·기간·토지기본 TXT의 명시적인 item 반영에 한정한다.

## 검토할 실패 조건

1. 다른 기관 또는 데이터셋의 item을 전달해도 미리보기·반영할 수 없어야 한다.
2. 적재 실패와 롤백 이후에도 실행 실패 기록이 남아야 한다.
3. 로그 종료 저장 실패를 데이터 적재 실패로 잘못 안내하거나 자동 재시도하지 않아야 한다.
4. 용도지역 일부 실패가 전체 성공으로 보이지 않아야 한다.
5. 새로고침·재수집 실패 후 이전 item을 잘못 선택해 반영하지 않아야 한다.

## 실행 기록

- 변경 전 `gradlew.bat test`: 45개 중 1개 실패. `DatabaseDefaultsTest.resolvesApprovedPostgresDefaultsWithoutEnvironmentOverrides`의 기존 기본값 불일치. 이번 기능과 분리해 최종 결과에 보고한다.
- 실행 로그·이력 클래스 부재로 실패한 테스트를 구현 후 통과시켰다. 반영 조회의 데이터셋 격리 누락과 초기 반영 버튼 활성화를 회귀 테스트로 재현한 뒤 수정했다.
- 별도 코드 검토에서 안내 문구 인코딩 및 용도지역 상태 갱신 누락을 확인하고 수정했다. 요청 식별 요약도 추가했다.
- 새 테스트 14개 통과. 전체 59개 중 58개 통과, 기존 기본값 테스트 1개 실패 유지.
- 브라우저 테스트 통과, `bootJar` 성공. 결과 문서: `docs/reference/2026-09-22/kras-integration-phase1-implementation.md`.
- 결정: 실제 운영 API를 호출하거나 운영 데이터에 신규 반영하지 않고 테스트 대역으로 검증했다. 실제 연계 환경의 입력·권한 및 DB 동작은 배포 시 확인이 필요하다.
